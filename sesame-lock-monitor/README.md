# セサミ 鍵の閉め忘れ監視（Google Apps Script）

Sesame Web API で鍵の状態を取得し、**解錠したままなら LINE に警告を飛ばす** GAS スクリプトです。

- `Code.gs` … 本体
- `appsscript.json` … タイムゾーン等（`Asia/Tokyo`）

---

## ⚠️ 最初に読んでください：LINE Notify について

**LINE Notify は 2025年3月31日をもってサービス終了しました。** 新規トークンの発行も、既存トークンでの送信もできません。
ネット上に残っている「LINE Notify で通知する GAS 記事」は、現在そのままでは動きません。

そのため本スクリプトは通知経路を切り替え式にしています。

| 経路 | プロパティ `NOTIFIER` | 状態 |
|---|---|---|
| LINE Messaging API（プッシュメッセージ） | `messaging`（既定） | ✅ 現行・推奨 |
| LINE Notify | `notify` | ❌ 終了済み（コードは互換のため残置） |

以下の手順は **Messaging API 前提**で書いています。

---

## 0. 前提条件

- セサミ本体に **Wi-Fiモジュール2（WM2）** が接続済みであること。
  Bluetooth のみの構成だとクラウド側に状態が上がらず、Web API から現在の状態を取得できません。
- Google アカウント（GAS 用）
- LINE アカウント

---

## 1. セサミ側の準備（APIキー / デバイスUUID）

### 1-1. APIキーを取得する

1. CandyHouse の開発者向けダッシュボード <https://partners.candyhouse.co/> にアクセス
2. メールアドレスで登録・ログイン
3. API Key を発行してコピー（この値が `SESAME_API_KEY`）

> APIキーは「そのアカウントのセサミを操作できる鍵」そのものです。GitHub 等に絶対に貼らないでください。

### 1-2. デバイスUUIDを調べる

セサミアプリを開き、対象のデバイス → 設定（歯車）→ デバイス情報 / QRコード 付近に
`XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX` 形式の UUID が表示されます（アプリのバージョンで文言が異なります）。
これが `SESAME_DEVICE_UUID` です。

### 1-3. API の仕様（このスクリプトが使う部分）

```
GET https://app.candyhouse.co/api/sesame2/{UUID}
Header: x-api-key: {APIキー}
```

レスポンス例：

```json
{
  "batteryPercentage": 94,
  "batteryVoltage": 5.87,
  "position": 11,
  "CHSesame2Status": "locked",
  "timestamp": 1700000000,
  "wm2State": 1
}
```

## 2. LINE 側の準備（Messaging API）

1. <https://developers.line.biz/console/> にログイン
2. **プロバイダー**を新規作成（名前は任意、例：`home`）
3. その中に **Messaging API チャネル**を作成
4. 「Messaging API設定」タブ →**チャネルアクセストークン（長期）** を発行してコピー
   → これが `LINE_CHANNEL_ACCESS_TOKEN`
5. 同じタブに表示される **QRコード**を自分のスマホの LINE で読み取り、**Bot を友だち追加**
   （友だちになっていないアカウントにはプッシュ送信できません）
6. 「チャネル基本設定」タブの **`Your user ID`**（`U` から始まる33文字）をコピー
   → これが `LINE_TO`（＝自分宛に送るための送信先ID）

> 補足：無料プランでもプッシュメッセージは月200通まで送れます。閉め忘れ通知の用途なら十分です。
> また「応答メッセージ（自動応答）」は LINE Official Account Manager 側でオフにしておくと静かになります。

---

## 3. GAS プロジェクトの作成

1. <https://script.google.com/> → **新しいプロジェクト**
2. `コード.gs` の中身を全部消して、この repo の **`Code.gs` を丸ごと貼り付け**
3. プロジェクト名を「セサミ閉め忘れ監視」などに変更
4. （任意）左メニュー「プロジェクトの設定」→「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェックを入れ、
   タイムゾーンが **日本標準時（Asia/Tokyo）** になっているか確認

---

## 4. スクリプトプロパティの設定

左メニュー **⚙ プロジェクトの設定** → 一番下の **スクリプト プロパティ** → 「スクリプト プロパティを追加」

### 必須

| プロパティ | 値 |
|---|---|
| `SESAME_API_KEY` | 1-1 で取得した API キー |
| `SESAME_DEVICE_UUID` | 1-2 で調べた UUID |
| `LINE_CHANNEL_ACCESS_TOKEN` | 2-4 のチャネルアクセストークン（長期） |
| `LINE_TO` | 2-6 の `Your user ID`（`U…`） |

### 任意（未設定なら既定値で動く）

| プロパティ | 既定 | 説明 |
|---|---|---|
| `DEVICE_LABEL` | `玄関` | 通知文に出る場所名 |
| `NOTIFIER` | `messaging` | `notify` にすると LINE Notify 経路（現在は使用不可） |
| `TREAT_MOVED_AS_UNLOCKED` | `true` | `moved`（半端な位置）も警告対象にする |
| `NOTIFY_ON_UNKNOWN` | `false` | API 取得失敗・想定外の値でも通知するか |
| `ALERT_COOLDOWN_MINUTES` | `60` | 直前の通知からこの分数は再通知しない（連投防止） |

設定できているかは `showPropertyStatus()` を実行すると確認できます（値そのものはログに出しません）。

## 5. 動作確認

エディタ上部の関数プルダウンから選んで「実行」します。初回は Google の認可ダイアログが出るので、
「詳細」→「（プロジェクト名）に移動」→ 許可、と進めてください（外部通信 `UrlFetchApp` の権限が必要です）。

1. **`testFetchStatus()`** … API から状態が取れるか。実行ログに `CHSesame2Status` と判定結果が出ます。
2. **`testNotify()`** … LINE に実際にテスト送信されます。
3. **`checkSesameLock()`** … 本番と同じ処理。解錠中なら警告が飛びます。

> `testNotify()` のあとすぐ `checkSesameLock()` を試すとクールダウンで通知がスキップされることがあります。
> その場合は `resetCooldown()` を実行してください。

---

## 6. トリガー（定期実行）の設定

### 方法A：関数を実行するだけ（おすすめ）

エディタで **`createDailyTrigger()`** を実行 → 毎日23時台に `checkSesameLock` が走るトリガーが作られます。

- 30分おきに監視したい場合は **`createEveryThirtyMinutesTrigger()`**
- 全部消したい場合は **`deleteAllTriggers()`**

### 方法B：画面から手動で設定

1. 左メニュー **⏰ トリガー** → 右下「トリガーを追加」
2. 実行する関数：`checkSesameLock`
3. イベントのソース：**時間主導型**
4. 時間ベースのトリガーのタイプ：**日付ベースのタイマー**
5. 時刻：**午後11時〜午前0時**
6. 保存

> GAS の時刻指定は「23:00ちょうど」ではなく **「23時台のどこか」** です（1時間の幅があります）。
> 分単位で厳密にしたいなら、23時台に走らせた関数の中で `Utilities.sleep()` するか、
> 30分おきトリガー＋クールダウンで運用するのが現実的です。

### 運用のおすすめ

「毎日23時に1回」だけだと、23:05に開けっ放しにした場合は翌23時まで気づけません。
**平日夜だけ30分おき**など、生活パターンに合わせて複数トリガーを作るのが実用的です。

## 7. 施錠 / 解錠の判定ロジック

判定は必ず **`CHSesame2Status`** を正とします（`Code.gs` の `interpretLockState_()`）。

| `CHSesame2Status` | 意味 | 本スクリプトの扱い |
|---|---|---|
| `"locked"` | 施錠済み | 通知しない |
| `"unlocked"` | 解錠 | ⚠️ **通知する** |
| `"moved"` | サムターンが中途半端／動作中 | `TREAT_MOVED_AS_UNLOCKED=true`（既定）なら通知 |
| その他 / 取得失敗 | 不明 | `NOTIFY_ON_UNKNOWN=true` のときだけ通知 |

実装上の注意点：

- **大文字小文字・前後の空白を吸収**して比較しています（`"Locked"` でも `" unlocked "` でも正しく判定）。
- SDK やファームによっては **数値（0=locked / 1=unlocked / 2=moved）** で返ることがあるため、そちらも解釈します。
- **`position`（角度）だけで判定してはいけません。** 取り付け角度は個体ごとに違うため、
  「何度なら施錠」は一般化できません。角度は参考値です。
- `wm2State` は Wi-Fi モジュールの接続状態です。ここが切れていると `timestamp` が古いままになるので、
  通知文には最終更新時刻も入れています。

## 8. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `HTTP 401 / 403` | APIキーが違う、またはそのUUIDへの権限がない。`SESAME_API_KEY` を再確認 |
| `HTTP 404` | UUID の間違い。ハイフン込みで正しくコピーできているか確認 |
| 状態が古いまま更新されない | WM2 がオフラインの可能性。セサミアプリでWi-Fiモジュールの接続を確認 |
| LINE に届かない（`HTTP 403`） | Bot を友だち追加していない、または `LINE_TO` が別人のID |
| LINE `HTTP 429` | 無料枠の月間送信上限。クールダウンを長めに設定するか、プランを見直す |
| LINE Notify で `HTTP 401` | サービス終了済みのため。`NOTIFIER` を `messaging` にしてください |
| 実行ログに「スクリプトプロパティが未設定です」 | 表示されたキー名を設定。`showPropertyStatus()` で確認できます |

---

## 9. セキュリティ上の注意

- APIキー・チャネルアクセストークンは**すべてスクリプトプロパティ**にあり、コードには含まれません。
- そのため **このプロジェクトを他人と共有すると、共有相手はプロパティも見られます**。編集権限の共有は慎重に。
- トークンが漏れた場合は、LINE Developers 側でチャネルアクセストークンを再発行（旧トークンは失効）、
  CandyHouse 側で API キーを再発行してください。
