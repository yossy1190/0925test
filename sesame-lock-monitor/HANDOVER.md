## 1. 作りたいもの

自宅玄関のスマートロック **SESAME 5 Pro** の施錠状態を定期的に確認し、
**解錠したままだったときだけ** LINE に警告を飛ばす仕組み。

- 実行環境: **Google Apps Script（GAS）**
- 状態の取得: **Sesame Web API**（`https://app.candyhouse.co/api/sesame2/{UUID}`）
- 通知: **LINE Messaging API**（プッシュメッセージ）
- 通知文の例: `⚠️警告：玄関のセサミが開いたままです！`
- 認証情報はコードに直書きせず、**GASのスクリプトプロパティ**から読む

依頼者は非エンジニア。手順は画面名・ボタン名まで具体的に示す必要がある。

## 3. 現在のブロッカー（詳細）

### 症状

GASエディタで関数 `showPropertyStatus` を実行すると：

1. 実行ログに警告が出る
   ```
   このプロジェクトを実行するには、ご利用の Google アカウントへの
   アクセスを許可する必要があります。再試行して、許可してください。
   ```
2. 別ウィンドウ（`accounts.google.com/signin/oauth/warning?authuser=0&part=...`）が開き、赤い警告アイコンとともに表示される
   ```
   このアプリはブロックされます
   このアプリが、Google アカウントのプライベートな情報にアクセスしようとしました。
   アカウントを安全に保つため、Google によりこのアクセスはブロックされました。
   ```
3. **この画面には「詳細」リンクが無く、迂回できない。**
   よく解説されている「詳細 →（プロジェクト名）に移動 → 許可」の画面には到達しない。
   つまり「確認されていません」の警告ではなく、**完全なブロック**。

### 環境（切り分け済みの事実）

- Googleアカウント: **個人の @gmail.com**（Google Workspace / 組織アカウントではない）
- GASプロジェクト: **script.google.com から新規作成したスタンドアロン**
  （スプレッドシート等に紐づいたコンテナバインドではない）
- ブラウザ: Windows版 Chrome
- コードが使うGoogleサービス: `UrlFetchApp` / `PropertiesService` / `ScriptApp`（トリガー作成）/ `Utilities` / `console` のみ
- 外部通信先: `app.candyhouse.co` と `api.line.me` の2つだけ

### 試したこと（いずれも同じ結果）

- Chromeのシークレットウィンドウで、対象アカウント1つだけログインして実行
- GASプロジェクトを新規に作り直して実行

### 検討したが否定された仮説

| 仮説 | 否定した根拠 |
|---|---|
| 組織（Workspace）アカウントの管理者ポリシー | 個人の @gmail.com だった |
| 複数アカウント同時ログインによる `authuser` の食い違い | シークレットウィンドウでも同症状 |
| 組織所有ファイルに紐づくコンテナバインドスクリプト | スタンドアロンで新規作成したもの |
| コードの構文エラー | エディタ上489行で正常に閉じている。エラーは認可段階のもの |

### 未実施の対策（次の一手）

1. **Googleアカウントが「高度な保護機能プログラム」に登録されていないか確認**
   `myaccount.google.com/security`。登録されていると未確認のサードパーティアプリは
   完全にブロックされ、迂回リンクも出ない。症状と一致する。
2. **標準のGoogle Cloudプロジェクトを作成してGASに紐付ける**
   - Cloud Console でプロジェクト作成 → **プロジェクト番号**を控える
   - OAuth同意画面（新UIでは Google Auth Platform）を設定：対象＝**外部**
   - **公開ステータスを「本番環境」にする**
     ← テストのままだと認可が **7日で失効**し、毎日のトリガーが止まる。重要。
   - GASの「⚙ プロジェクトの設定 → Google Cloud Platform（GCP）プロジェクト」で
     プロジェクト番号を設定
   - 再実行し、「ブロックされます」→「**確認されていません**」に変われば突破。
     後者は「詳細 → 移動 → 許可」で自分で通せる。
3. 上記でも解決しない場合、**この監視専用に新しいGoogleアカウントを作る**。
   ブロック履歴のないアカウントなら通る可能性が高い。

## 4. 設計上の決定事項（と、その理由）

引き継ぐ側が「なぜこうなっているのか」で迷わないための記録。

### 4-1. 通知は LINE Notify ではなく LINE Messaging API

**LINE Notify は 2025年3月31日でサービス終了**しており、新規トークン発行も送信もできない。
ネット上の「GAS × LINE Notify」の記事は現在すべて動作しない。

コードは通知経路を切り替え式にしてあり、スクリプトプロパティ `NOTIFIER` で選ぶ。

| 値 | 経路 | 状態 |
|---|---|---|
| `messaging`（既定） | LINE Messaging API プッシュ | 現行・これを使う |
| `notify` | LINE Notify | 終了済み。互換のため実装だけ残置 |

無料枠でプッシュは月200通まで。閉め忘れ通知には十分。

### 4-2. 施錠判定は `CHSesame2Status` を正とする

`position`（サムターンの角度）で判定してはいけない。取り付け角度が個体ごとに違うため
「何度なら施錠」は一般化できない。

| `CHSesame2Status` | 意味 | 扱い |
|---|---|---|
| `"locked"` | 施錠済み | 通知しない |
| `"unlocked"` | 解錠 | **通知する** |
| `"moved"` | 中途半端な位置／動作中 | 既定で通知（`TREAT_MOVED_AS_UNLOCKED` で切替） |
| その他・取得失敗 | 不明 | 既定では通知しない（`NOTIFY_ON_UNKNOWN` で切替） |

実装上の配慮：
- 大文字小文字と前後の空白を吸収（`"Locked"` や `" unlocked "` でも正しく判定）
- SDK・ファーム差で**数値**（0=locked / 1=unlocked / 2=moved）が返る場合も解釈

### 4-3. その他の実装方針

- 認証情報4種はすべてスクリプトプロパティから読み、起動時に必須チェック（不足キー名をログ出力）
- HTTP 5xx / 429 は指数バックオフで3回まで再試行。4xxは即エラー（401/403/404は日本語で出し分け）
- **通知の連投抑止**（既定60分）。30分おき監視にしても鳴り続けない
- 通知文に**電池残量**と**最終更新時刻**を付加
  → この時刻が古いままなら、鍵ではなく**Wi-Fiが切れている**サインとして読める
- トリガー作成/削除は関数化（`createDailyTrigger` 等）。UIから手作業で作る必要がない

## 5. 途中で判明した事実（ハマりどころ）

同じ道を通る人が繰り返さないための記録。

### 5-1. APIキー発行ページのドメインが消滅している

各所（公式ヘルプ含む）で案内されている **`partners.candyhouse.co` は DNS が解決しない**。
`dash.candyhouse.co` も同様。ブラウザでは `DNS_PROBE_FINISHED_NXDOMAIN` になる。

生きているホスト（DNS確認済み）: `app.candyhouse.co`（API本体）、`jp.candyhouse.co`、
`doc.candyhouse.co`、`biz.candyhouse.co`、`my.candyhouse.co`、`api.candyhouse.co`

**→ 最終的に APIキーは取得できた。** ただし正確な発行経路の記録は未取得（要追記）。
`my.candyhouse.co` が生きていることを手がかりに到達した。

### 5-2. 「クラウド連携」は Sesame 5 系には存在しない

公式ヘルプの「セサミの管理 → クラウドの連携をON」は **Sesame 3 / 4 世代向け**。
Sesame 5 / 5 Pro（SesameOS3）の設定画面にこの項目は無く、探しても見つからないのが正常。
5系ではクラウド接続は Wi-Fiモジュール2 が担当する。

### 5-3. デバイスUUIDはアプリで取れる

対象のセサミ → 右上の ⋮ → 設定画面を**一番下までスクロール**すると UUID が表示される。
**コピーできない仕様**なので、スクリーンショットを撮るか手で書き写す。

### 5-4. LINE Developers で必要なのは2つだけ

紛らわしいが、**Channel ID と Channel secret は使わない**。

| 必要な値 | どのタブ | 欄の名前 |
|---|---|---|
| `LINE_TO` | チャネル基本設定 | **あなたのユーザーID**（ページ下部、`U`で始まる） |
| `LINE_CHANNEL_ACCESS_TOKEN` | Messaging API設定 | **チャネルアクセストークン（長期）** の発行ボタン |

さらに、**Messaging API設定タブのQRコードでBotを友だち追加**しないと通知は届かない。
これを忘れて「送信エラー」で悩むのが最頻出のミス。

### 5-5. Googleアカウントは Google/Facebook ログインだとWeb側に入れない場合がある

CANDY HOUSE のダッシュボードはメール＋パスワードでログインする。
アプリに Google / Facebook で登録している場合はパスワードが存在しないため、
先にアプリの「設定 → パスワードの変更 → パスワードの設定」でパスワードを作る必要がある。

## 9. 運用時の注意点

- **GASの時間主導型トリガーは「23時ちょうど」ではなく「23時台のどこか」**（分は指定不可）。
  23時の1回だけだと23時05分に開けっ放しにした場合は翌日まで気づけないため、
  **夜間は30分おき＋クールダウン**のほうが実用的。
- **通知が来ないのが正常。** 施錠されていれば何も起きない。
- この仕組みは**鍵の状態しか見ていない**。ドアが半開きかどうかは分からない。
- GASプロジェクトを他人と共有すると、**共有相手はスクリプトプロパティ（＝APIキー）も見られる**。
- 鍵の操作権限そのものであるAPIキーは、漏れたら再発行すること。
